# 삼바브라우저 사용 방법 (초보자용)

> 설치·첫 실행은 **[README 의 3분 퀵스타트](../README.md#3분-퀵스타트)** 가 기준입니다.
> 이 문서는 그 다음 단계 — 화면별로 무엇을 어떻게 쓰는지 — 를 다룹니다.

## 1. 아주 짧게
```bash
corepack enable
pnpm install
pnpm dev
```
매일 실행은 프로젝트 폴더에서 `pnpm dev` 하나면 됩니다.

## 4. 써보기
- 오른쪽 채팅에 "구글 열어서 삼바웨이브 검색해" 입력 → AI가 진행 로그를 보여주며 수행
- 진행 띠의 [중단]으로 멈춤
- 주소창 옆 PC / 모바일 로 화면 전환
- 위험한 행동(결제·구매·삭제 등)은 채팅창 아래에 노란 확인 카드가 뜸 → [승인] / [거부]
  - 확인 카드는 **클릭·입력** 행동에만 나옴. 주소 이동(navigate)은 확인 없이 진행됨
- 왼쪽 **키마스터**: 마스터 비밀번호 설정 후 CSV(비밀번호)·HTML(북마크) 가져오기. 로그인창의 아이디 칸을 누르면 저장된 계정 목록이 바로 뜨고, 고르면 자동 입력
- AI 에게 "네이버 로그인해" 라고 하면 키마스터의 계정으로 로그인. 이미지 캡차는 AI 가 화면을 보고(`screenshot`) 또는 글자를 읽어서(`ocr`) 처리
- 로컬 OCR 은 처음 쓸 때 한국어 인식 모델(약 18MB)을 `%APPDATA%\SAMBA Browser\models\ocr` 에 한 번 내려받음. 인터넷 필요

## 4-1. 계정 만들고 두 PC 연결하기 (2b)
1. **Supabase 준비**(한 번만): 동기화는 각자 자기 Supabase 프로젝트에 붙는다. [README 의 "내 Supabase 만들기"](../README.md#선택-내-supabase-만들기--다기기-동기화용) 대로 무료 프로젝트를 만들고 `supabase/schema.sql` 을 실행한 뒤, 앱 → **설정 → 계정 → Supabase 연결** 에 프로젝트 URL 과 anon 키를 붙여넣고 앱을 다시 시작한다. `.env` 에 넣어도 되고(`.env` 는 절대 커밋하지 않는다), 안 만들면 동기화 없이 이 PC 에서만 쓴다
2. 앱 → 설정 → **계정** → 회원가입(이메일·비밀번호) → 바로 로그인됨. Supabase 의 "Confirm email" 이 켜져 있으면 메일 확인 후 로그인
3. 로그인되면 기존 계정·북마크·설정이 자동으로 서버에 올라간다(수천 건이면 1~2분). 설정 → 계정 → 동기화 상태의 "대기 변경" 이 0 이면 완료
4. **두 번째 PC**: 같은 방법으로 앱을 설치하고 같은 계정으로 로그인 → 키마스터 탭에서 **첫 PC 와 같은 마스터 비밀번호** 입력 → 계정·북마크·키마스터·설정·채팅이 내려온다(60초 주기, "지금 동기화" 로 즉시)
5. 설정 → 계정 → 기기 목록에서 다른 PC 를 **원격 로그아웃** 할 수 있다(그 PC 는 다음 주기에 로그아웃·키마스터 잠금)
   - ⚠️ **채팅 내용은 암호화 없이 평문으로 서버에 올라간다**(키마스터의 비밀값만 기기에서 암호화된다). 대화에 비밀번호·카드번호 같은 값을 적지 않는다
6. 복구 키: 설정 → 보안 → **복구 키 재발급** → 24자 키를 안전한 곳에 보관. 마스터 비밀번호와 복구 키를 둘 다 잃으면 키마스터를 열 수 없다

## 4-2. 폰 연동 (3단계, Pro)
1. 폰에서 **개발자 옵션 → USB 디버깅** 켜고 USB 로 PC 에 연결(첫 연결 시 폰에 뜨는 "USB 디버깅 허용" 승인)
2. 앱 → **폰** 화면 → 도구 카드에서 **adb·scrcpy 설치**(원클릭, 앱 데이터 폴더에 내려받음). 이미 깔려 있으면 경로만 확인
3. 기기 목록에 폰이 뜨면 **연결** → 화면 스트림·문자 권한 확인. 사이트별로 인증 폰을 지정할 수 있다
4. AI 작업 중 문자 인증번호는 자동으로 읽어 채우고, 결제 승인은 앱 안 폰 화면에서 **사용자가 직접** 비밀번호를 누른다(AI 는 그 화면을 보지 않는다)

## 4-3. 새 기능 빠르게 써보기 (3단계)
- **제스처**: 페이지에서 오른쪽 버튼을 누른 채 ← / → / ↑ / ↓ 로 끌기. 설정 → 동작 → 마우스 제스처에서 조합 변경
- **번역**: 주소창 오른쪽 번역 아이콘 → 대상 언어 → "이 페이지 번역". 이미지는 우클릭 → 이미지 번역
- **캡처**: 주소창 카메라 아이콘 또는 `Alt+1~6`. 저장 폴더는 설정 → 일반 → 캡처
- **확장**: 확장 페이지 → "확장 설치" → 웹스토어에서 원하는 확장의 **Chrome에 추가** 클릭

## 5. 문제가 생기면

자주 나는 설치 오류(postinstall·포트·방화벽)는 [README 의 문제 해결](../README.md#문제-해결) 표를 먼저 보세요.

| 증상 | 해결 |
|---|---|
| 채팅에 노란 띠 "AI 연결이 안 됐어요" | 터미널에서 `claude login` |
| "사용 한도" 띠 | 몇 시간 뒤 재시도 또는 설정에서 API 키 |
| AI가 오래 응답이 없음 | 구독 사용 한도일 수 있음. 진행 띠의 [중단] 누르고 잠시 후 재시도 |
| 탭을 바꿨는데 본문만 하얗게 남음 | 탭 전환 뒤 자동으로 화면을 다시 붙여 그린다. 계속 하얗다면 `Ctrl+Alt+R`로 화면만 복구한다. 이 동작은 페이지를 새로고침하지 않는다. |
| `pnpm` 없다고 나옴 | `corepack enable` 후 터미널 다시 열기 |
| 코드를 고쳤는데 앱에 반영이 안 됨 | 화면(renderer)은 저절로 반영되지만 `src/main`·`src/preload` 변경은 앱을 닫고 `pnpm dev` 다시 실행 |
| 로그인창에 계정 목록이 안 뜸 | 키마스터가 잠겨 있으면 "잠금 해제 필요"만 뜸. 왼쪽 키마스터에서 해제 |
| OCR 이 "모델 없음" | 인터넷 연결 확인 후 다시 시도(첫 1회 다운로드) |
| 로그인 시 "이메일 또는 비밀번호가 맞지 않아요" | 가입 때 쓴 비밀번호 확인. Supabase 대시보드 Authentication → Users 에서 상태(확인 대기 여부) 확인 |
| 두 번째 PC 에 데이터가 안 내려옴 | 첫 PC 의 "대기 변경" 이 0 인지, 두 번째 PC 에서 "지금 동기화" 눌렀는지 확인 |

## 6. 코드 검사
- `pnpm test` — 자동 테스트
- `pnpm lint` — 코드 규칙 검사

### 탭 전환·클릭 지연 개선 기록 (2026-10-25)

- 확인한 원인: 탭 전환마다 모든 WebContentsView를 떼고 다시 붙이는 비용이 컸다. 또한 뒤 탭 캡처/스크롤용 `withFront`가 사용자 화면 위에 작업 탭을 올리고 캡처 완료까지 유지했다. 실제 로그에 22.8초 캡처 대기가 있었으며, 선택한 르무통 탭 대신 SSG 본문이 보이는 불일치를 관찰했다. 읽기 전용 캡처에는 `runAsAutomation` 표식이 없는 경로도 있어, 자동화 표식만 검사하면 화면 보호가 빠졌다.
- 최종 변경: 전환 때 필요한 뷰만 추가·제거하고 선택한 탭을 앞으로 옮긴다. 같은 탭 재선택은 재부착하지 않으며 활성 탭의 스로틀링을 다시 켜지 않는다. 캡처/스크롤 자체에서 브릿지 출처·최근 사람 입력을 판정해 보이는 탭을 덮지 않고, 전면 작업 종료 시 현재 선택한 탭을 복원한다.
- 표시 복구: 일반·뒤 층·휴면 탭 전환에 150ms·1200ms 복구를 예약한다. 전환 세대가 바뀌거나 사람이 입력한 뒤에는 오래된 복구를 실행하지 않는다. 대상 뷰만 다시 붙이며 1px 크기 변경은 32ms 유지한 뒤 복원한다. 중복 요청·새 창 배치·종료·로그인 게이트·캡처 중 재배치를 보호한다.
- 최종 속도 시험: 별도 사용자 데이터의 실제 Electron 39.8.10 창, 단순 로컬 페이지 12개, 36회 전환. 기존/최종 전환 중앙값 128.8/8.5ms, 95백분위 164.6/14.1ms. 페이지 rAF 응답 중앙값 147.7/16.7ms, 95백분위 186.3/19.4ms. 전후 시간 초과 0회. 뷰 추가/제거는 432/432회에서 36/0회로 감소했다. 시점이 다른 로컬 통제 시험이며 Windows 화면 합성 완료나 외부 사이트 전체 로딩 시간의 측정은 아니다.
- 자동 검증: 관련 8개 파일 103개 검사, 타입 검사, ESLint, 빌드 통과. 일반·뒤 층 탭, 빠른 왕복, 중복 갱신과 새 배치 보호, 브릿지 및 읽기 전용 캡처의 화면 보호, 캡처 중 사용자 탭 변경 후 복원 등을 포함한다.
- 실제 창 검증: 르무통 홈에서 `men`을 눌러 `/product/list_men.html?cate_no=63`, SSG 홈에서 `베스트`를 눌러 `/page/pc/ranking.ssg`의 본문과 제목을 확인했다. 최종 소스로 21:01 재시작한 PID 36748에서 두 페이지를 다시 전환해 선택 표시·주소·본문 일치를 확인했다. 르무통을 보면서 뒤쪽 SSG를 MCP로 캡처해 697×764 응답을 받았고, 같은 구간에 `front-start` 없이 르무통 화면이 유지됨을 확인했다. 인증 입력·구매·주문 변경은 하지 않았다.
- 캡처 호환성: 시험했던 `setVisible(false)` 방식은 새 탭 캡처에 0×0 이미지가 반환되어 최종 코드에서 제외했다. 응답 객체만 확인하는 시험으로는 유효한 이미지 크기를 보장할 수 없다. Electron 42.9.2도 별도로 비교했지만 엔진 변경을 해결 근거로 확정하지 않아 의존성은 유지했다. 관련 공식 이력: https://releases.electronjs.org/pr/52844
- 로그인 연결 복구: 이전 빌드는 DNS에서 조회되지 않는 옛 내장 계정 서버를 사용했다. 기존 로컬 설정과 저장 세션이 가리키는 서버에서 사용자 확인·디렉터리 설정 조회 HTTP 200을 확인한 뒤, 이 PC의 Git 제외 `.env`에 기존 서버 지정을 보존했다. 비밀번호 변경·계정 이동은 하지 않았다.
- 재빌드·재시작 유지: 프로세스의 `SAMBA_DIRECTORY_URL`·`SAMBA_DIRECTORY_ANON_KEY`를 비운 실제 빌드와 재시작을 검증했다. Vite가 `.env`에서 읽은 서버 주소·키가 최종 빌드 및 기존 로컬 설정과 일치함을 값 노출 없이 대조했으며, 재시작한 앱은 저장 세션으로 진입했다. 이 PC의 현재 작업 폴더에서 `.env`가 보존되는 조건이다. Git 소스만 다른 PC로 복사할 때는 별도 설정이 필요하다.
- 외부 사이트 대기: 별도 르무통 관찰에서 홈 문서 약 1.9초·라이브쇼핑 설정 약 17.4초가 걸렸다. 사용자가 첨부한 휴대폰 인증과 같은 거래의 측정이 아니므로 이를 인증 지연의 원인으로 단정하지 않는다. 모든 사이트의 로딩 시간을 보장하는 변경은 아니다.
